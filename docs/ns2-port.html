Switch 2 (NS2) in the Tears of the Kingdom runtime

NS2 dumps containing only ExeFS/RomFS have no Control-NCA icon. A game's assets/app-icon.json can identify its official image by URL and SHA-256; preparation caches the verified image and generates build/AppIcon.icns outside the source tree. Both the Mac app and the iOS asset catalog use that icon. Check the packaged CFBundleIcons, Assets.car, and the installed phone's SpringBoard icon image; a successful build alone does not prove that a home-screen icon exists.

Branch ns2 (started 2026-11-02). Goal: Switch 2 games run on the same runtime as Tears of the Kingdom and Breath of the Wild (games/totk/runtime, third_party/d2r_gfx, the totk_xlate translator), not as a separate copy of another project. First target: Donkey Kong Bananza (title 040074A01BF12000, update v458752, SDK 20.5.19, NVN2) on the Mac, because seedds/nxnative (MIT) already runs it there and every step can be compared with it.

Phases

Each phase ends with a check that needs no one at the keyboard, and is committed on ns2 on its own.

Rules for this work

  • Port behaviour, not copies: each change is read in nxnative, written into our code where our code does the same thing, and credited (from seedds/nxnative <commit>, MIT) in the comment, as earlier ports from it.
  • No Bananza-only branches where a Switch 2 rule holds for every Switch 2 game (NVN2, SDK 20 / 21): key them on what the module shows (its NVN2 control sections, its SDK version), the way the runtime already keys TotK and BotW behaviour.
  • The TotK and BotW builds must not change: every phase that touches shared code is checked against them (the translator replay scripts/diag/retranslate_cache.py --compare for phase 1; their unit tests and a Mac boot for the rest).

Pokopia, evening 2026-11-03: the GPU hang is fixed; the game reaches its language selection.

  • Cause: a translator bug. A two-source half-pair operation (HADD2, HMUL2, HSET2, HSETP2, HMNMX2) in forms 2, 3 and 7 takes its second source from the 32-bit slot (here an immediate); patch 0006 took the unused register field at 64 instead (R0). Fragment shader 85446a67 (a bilateral blur) steps its loop with HADD2 R6, R6, 2.0, 2.0: the step became the bits of whatever R0 held, the loop never ended, the GPU hung, and macOS reset the GPU for every app (other apps' renderers failed too). Fixed as seedds/nxnative 03d92a9f (MIT) does: AHalfSecond, and an immediate's bits 62 / 63 are not modifiers. It changed 260 of Pokopia's 2,384 translations; Bananza's are Ampere too (its cache needs translating again).
  • Found without hanging the GPU again: DM_NVN_SKIP_FS=<prefixes> (up to 16) halves the fragment shaders whose draws are skipped; TOTK_FS_UBO_DUMP=<folder> (new) writes the uniform buffers a skipped draw would have read. A hang test that hangs resets the whole GPU: run such bisections only with the user's agreement.
  • Also: a compute pipeline whose kernel does not take its declared thread group is built again for it (nvn_mtl.m cs_new; none of Pokopia's needed it).
  • Open: Pokopia's offline corpus misses some shaders the game draws. 85446a67 was translated at run time, and no 32-byte window of its instructions (but the common tail) is in the modules, LINKDATA or any IDRK entry, decompressed: it is not stored as it is drawn (made or changed at load, or in a container not read yet).

Pokopia, night 2026-11-04: all of its shaders found; one ID space per descriptor pool; two more NVN2 calls.

  • The shader extractor missed 98 % of the game's shaders. scripts/ns2_shader_corpus.py found the control section from other header fields and took it as 0xe0 bytes long; the GLSLC header gives the control section's offset (+0x60) and the control section its own size (+0x30) and the code length (+0x44), as kirakira-dev/ouncenative's nx2_shader_extract.py (MIT) reads them. Pokopia's files hold 131,090 distinct shaders (RDB data 130,904, LINKDATA 26, modules 160), not 2,385; of the 8,026 the game set in a 4-minute run, 7,717 are among them (the earlier note that it makes most of its shaders while it runs was wrong: about 65 drawn ones are in no file).
  • The seed takes the modules' and LINKDATA's shaders and those of the RDB data the shared list names (ns2_shader_corpus.py --listed): all 131,090 would be about 23 GB of translations and libraries, and most are never loaded. The list holds the keys the game was seen to set (8,556 shaders, identifiers only); the runtime adds, to the player's contribution file, each shader the game sets that the seed lacks (totk_rt_note_set, GAME_NS2), so the list grows with play. shader_list.py prune refuses a Switch 2 list (its V rows are what the seed translates).
  • One ID space per descriptor pool (seedds/nxnative's design, MIT): each texture / sampler pool gets a base in the host table at its first initialisation; registrations go to base + ID, the handles a command buffer binds get the base of the pool it last bound, and the replay's bound check takes base + size of the bound pool. Pokopia's second texture pool registered textures over the first one's IDs in some scenes. Games with one pool of each kind keep base 0. Offline shader depth mode

Offline preparation does not execute the game's nvnDeviceSetDepthMode call. Its depth mode must therefore be an explicit build input: Bananza uses minus-w, Pokopia uses zero, as observed in their device setup. build_app.py passes this to prepare_ns2_seed.py --depth-mode; direct seed-shaders invocations must set TOTK_SEED_DEPTH_MODE. For minus-w, vertex translation converts clip z to (z+w)/2 for Metal. Applying the wrong convention can clip the entire fullscreen copy and leave the swapchain's previous contents on screen even with no missing shaders.

The seed manifest records nvn_depth_mode and translation_context_sha256 (runtime binary, translator and requested mode). Both offline translations and the app's writable shader cache use that context; changing it cannot reuse stale vertex translations under unchanged shader keys. Offline pipeline generation reads the mode from the same manifest.

Verification uses one real fullscreen vertex shader translated in both modes: only minus-w must contain the clip-z conversion. On the device, capture the presented swapchain texture, the final draw's actual uniform/vertex data and consecutive frames, then check the visible cropped output as well as the window screenshot. A draw submission count alone does not prove that the rasterizer produced pixels. Use a save copy and verify the restored original's hashes.
