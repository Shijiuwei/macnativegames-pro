# Mario Kart 8 Deluxe: changelog

## Status

What works and what does not: [README.md](README.md#status). This page says what changed, why, and how each change was checked; the detailed runs are in the [validation record](docs/validation.md).

## Where the code comes from

The runtime, graphics layer, rewriter, shader tools, Mac app packer and game profile are nxnative's ([seedds/nxnative](https://github.com/seedds/nxnative), commit `062cd06`, 2026-10-28), where Mario Kart 8 Deluxe was brought up (4.0.0 on 2026-10-23, 4.0.1 registered on 2026-10-26). The build wrapper, the input pins and the tests follow `games/jamboree`. What was copied and changed: [third_party/COPIES.md](third_party/COPIES.md).

All measurements on 28 October 2026: MacBook Pro, Apple M1 Max (GPU `applegpu_g13s`), 32 GB, macOS 27.0.1 (26A434), Xcode 27.1; the app built with `scripts/build_mk8d.py` from a base NSP and the 4.0.1 update NSP.

## Log

### 2026-10-30: 2P and every library applet, the keyboard as a player

- **Library applets take the game's focus** (upstream nxnative `137c2291`, GitHub issue #550, ported as it is). The host now holds the game out of focus while any applet stand-in runs (controller, keyboard, Mii, account, error, shop) and notifies the change both ways. It replaces this target's narrower fix of 2026-10-29, which sent the focus pair around the controller applet only.
- **2P with one controller** goes back to the engine class menu. The controller applet answers canceled when fewer players are connected than the game wants, as a player closing it would; with the earlier OK, the game opened the applet again every few frames (642 times in about 50 s, found after the fix of 2026-10-29).
- **Keyboard row** in the settings window (Controls): **Own player** makes the keyboard player 1 and the controllers players 2 on (the host's existing `DM_KBD_PLAYER=own`), so two can play with the keyboard and one controller. The default is as before.
- The import manifest marks the 14 newly changed files; the local patch holds all 22 changed files' diffs; `third_party/COPIES.md` describes both changes.
- **Checked:** `make -C games/mk8d test`, 21 tests: the copied `t_hid` and `t_oe` built and run (124 and 53 checks), and the settings row. Headless runs of a host built from these sources in a copy of the installed app: Minus on the character grid and on a variant panel, then on to the kart parts and the cup screen; 2P with one controller back to the engine class menu after one applet call ([validation record](docs/validation.md#2026-10-30-2p-and-every-library-applet)). Then the app built from this branch and installed, with the same results headless. By hand, with Keyboard on Own player and a DualSense, 2P reached its character select with two players; a solo session afterwards showed 47,382 of 47,400 frames and no audio underrun. Not checked: a race with two players.

### 2026-10-29: the Booster Course Pass, save backups

- **Save backups.** Before each start, the launcher (`runtime/mac/launcher.c`) clones the committed saves, `save/` and `save_device/`, into `backups/<date-time>/` beside them, and keeps the five newest; when both are byte for byte the newest backup's, it makes no new one. The game saves within seconds of every boot (5 bytes of `userdata.dat` change: a start count and a time), so each start that reaches the game adds a backup, while starts that stop before the game's first save (a build that fails at boot) push no good backup out. The copies are APFS clones, built in a `.partial` folder and renamed when complete. Only folders named like a backup are removed, and a failed backup is logged without stopping the game. The host's commits were already atomic (a working copy swapped in whole), so the backups are for a save the game itself spoiled, or one a new build should not have touched. As in Odyssey (`games/odyssey/scripts/odyssey_app_launcher.c`), but with clones, the unchanged check and a rename at the end. The import manifest marks `launcher.c` changed, in the local patch.
- **The controller applet no longer freezes the game.** Minus on the character screen opens the Switch's controller applet (`hid::ShowControllerSupport`). The game stops its scene for it and starts it again only on the focus message the system sends when the applet closes. The host answered the applet at once but sent no message, so the game stayed on a still frame at 60 fps and took no input until it was quit (reported by the player after a session by hand). The host's applet (`runtime/host/hle_hid.c`) now takes the game out of focus and back, as the system's applet does; the import manifest marks it and its test `t_hid.c` changed, both in the local patch (ten changed files in all, eight of them in the patch). The same code is in upstream nxnative. Checked: the copied host test `t_hid.c` (built by `tests/test_build.py`, 20 tests in all) checks the round trip of both applet forms; headless runs from a copy of the player's save froze the previous app after Minus on the character grid, and the rebuilt app went on after Minus on the grid and on a variant panel to the kart parts and the cup screen ([details](docs/validation.md#2026-10-29-the-controller-applet-froze-the-character-screen)).
- **README.** The settings window has no resolution or frame-rate rows for this game (they need rewriter patches it does not have); the launch section now lists what it does offer.

- **Inputs.** `build_mk8d.py` now links the Booster Course Pass (`0100152000023001`, `v65536`) when it is in the input folder, taken only by its own ticket: a file name alone, another add-on or another version of it is still left out or refused. The builder's gate (`target_inputs`, `TARGET_AOC`) accepts that one add-on and nothing else, and after upstream's `extract_aoc` writes its RomFS image (`aoc/1.img`, 4,228 bytes: `contents.dat` and `version.txt`), `verify_aoc` checks the image's size and SHA-256 against `assets/expected-4.0.1.json` before the shader split and the packer read it. The courses themselves are in the 4.0.1 update; the runtime already had everything else (nxnative's `aoc` and `MountAddOnContent` take-overs, the add-on content cache sized for this game, the launcher's `DM_AOC_DIR`, `pack_app.py --aoc`).
- **Moved originals.** A link in `<work>/input` whose original NSP has since moved or been renamed is replaced instead of stopping the build; any other file there still stops it.
- **Checked:** `make -C games/mk8d test`, 19 tests (the Booster Course Pass taken by its ticket and not by a name, other add-on content and versions refused, a changed image refused, the pins matching the gates, links to moved originals replaced; the launcher's backups compiled from `launcher.c` and run on APFS: none before anything is saved, none for unchanged saves, the five newest kept, an interrupted one cleared, a folder of the player's kept, a change in the device save alone backed up). A full build from the player's own three NSPs on current `main` (chain `d9fda03e8b0d`, SPIRV-Cross built at packaging), then scripted runs of the app: the host reports the add-on content and mounts it, and on the cup screen's next page (R) the first cup, the Golden Dash Cup, starts a 50cc race at Paris Promenade at 60 fps (2,997 frames on screen and 11 dropped in the race): [validation record](docs/validation.md#2026-10-29-the-booster-course-pass). Then, on the installed app: all 12 Booster cups on that page (without the add-on content, choosing one opens the game's purchase notice instead), a scripted Golden Dash Cup Grand Prix through three races' results and into Coconut Mall, and PR #1226's scripted race in full screen, which dropped 58 of 18,900 frames against 68 in a window ([the cup pages, a Grand Prix and full screen](docs/validation.md#the-cup-pages-a-booster-grand-prix-and-full-screen)). By hand, the player then played a whole Booster Course Pass Grand Prix in the app, in full screen with a DualSense, with no problem seen: 61,184 of 61,200 frames on screen in 17 minutes, no audio underrun ([by hand](docs/validation.md#by-hand-a-booster-grand-prix-in-full-screen)).

### 2026-10-28: games/mk8d, Mario Kart 8 Deluxe 4.0.1

- nxnative imported at `062cd06` into `runtime/`, `prebuilt/` and `third_party/nxnative/`, in `games/jamboree`'s layout; the import manifest records every file's upstream path and SHA-256 and marks the seven this target changes; the local patch holds the diffs of five of them (the profile's two are described in COPIES.md, since the lines they replace name RomFS files).
- **Inputs.** `build_mk8d.py` links only the base game and the 4.0.1 update from the input folder, chosen by their tickets; anything else, such as add-on content, is reported as ignored and never reaches the build. The build script stops before extraction on another title, another update or add-on content, and before the rewrite on any 4.0.1 ExeFS file whose size, SHA-256 or build ID differs from `assets/expected-4.0.1.json`.
- **No shader tables in Git.** Upstream's `shader_map.tsv` names the RomFS path each key first appears in, and at this commit its readers need that column. The profile carries no shader tables; every build splits them from the player's own 4.0.1 files into the work folder (upstream's derived-profile path, the one its full 4.0.1 race was reported with). The port's split gave the same shaders as an unmodified upstream build of the same files: 29,651 (12,530 vertex, 17,092 pixel, 28 compute, 1 geometry), the same stage and key in every map row, and byte-identical facts and 18,747 pairs; only the package names differ, by the generic group below. Its rewritten modules are byte-identical to upstream's too.
- **No RomFS names in the profile.** The extraction marker is the extraction root and one generic shader group replaces upstream's groups by RomFS folder, as in `games/jamboree`; the shader keys do not change.
- **Binary-only translator.** The Ryujinx-based translator is carried as checksummed binaries; `dmsh_chain.py` takes the translator's source hash from its lock instead of hashing a source checkout, so the chain version is this target's own (`d9fda03e8b0d`).
- **SPIRV-Cross is built at packaging** (after PR #1226): `build_mk8d.py` fetches release `vulkan-sdk-1.4.363.0` (commit `f11ba9f`), checks the commit, and compiles its 11 sources with clang; the lock pins its `--revision` rather than its bytes, which differ between compilers. On 1,204 shaders its MSL is byte-identical to the binary the PR carried.
- **Offline build.** LibHac 0.19.0 comes from a local, SHA-256-pinned package through a NuGet configuration that clears every other feed, with NuGet auditing off; .NET's caches stay in the work folder. glslang is no longer required (an OpenGL game's tool).
- **Online and local wireless** are cut by the host as upstream has them: nifm reports no network, ldn never initializes.
- **Checked:** scripted runs of the built app (the title, the Mii pick, a full 50cc Grand Prix race to the results at 60 fps, the online and wireless menus) and two sessions by hand with a DualSense. The race by hand was in the unmodified upstream build used for the comparison, and the start by hand was in this target's app: [validation record](docs/validation.md).
